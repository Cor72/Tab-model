# 2026-09-27

## v0.1 代码 review（用户自己写的 model.py + cli.py）

项目实际建在仓库根目录（不是 local-completion/ 子目录），venv 在 `./.venv`，Python 3.11。
`app/completion.py` 和 `app/__init__.py` 仍为空。

### 实测基准（Qwen3-0.6B，CPU，i5-13420H，8 线程）

| dtype | 加载 | 速度 |
|---|---|---|
| bfloat16 | 2.9s | 8.3–10.2 tok/s |
| float32 | 2.7s | 8.9–9.5 tok/s |

结论：**bf16 和 fp32 速度基本持平**，bf16 只是省内存，保持 bf16 即可。

### 发现的问题（按严重度）

1. `device_map="cpu"` 直接崩溃 —— 需要 accelerate 但未安装。删掉该参数即可（默认就在 CPU）。
2. 补全质量差：greedy 解码导致复读（"东京的大学的图书馆的咖啡厅的…"），
   且 instruct 模型会把续写变成"自问自答式的评论文本"。
3. 模型不会自己停，48 token 全部撑满、截断在句子中间 → 缺停止条件。
4. 8–10 tok/s 对 inline completion 偏慢。

### 下一步方向

- 加停止条件（句号 / 换行 / 重复检测），这是 v0.1 就该有的
- 治本方案：换 `Qwen/Qwen3-0.6B-Base`（真正的 base 权重，已确认 ModelScope 上有）
- 提速留到量化阶段（GGUF / llama.cpp）
